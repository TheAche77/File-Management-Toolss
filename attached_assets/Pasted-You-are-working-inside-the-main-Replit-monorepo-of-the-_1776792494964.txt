## REVIEW AND INTEGRATION PRINCIPLES

Use these principles:

### 1. Preserve value, not accidents

If Codex-added code is good, keep it and integrate it.
If legacy code is better, preserve that instead.
If both contain value, merge intelligently.
Do not blindly favor old or new code.

### 2. Prefer one strong implementation over multiple weak ones

If there are now two versions of the same feature, consolidate them.
Avoid duplicated routes, duplicated components, duplicated utilities, duplicated schemas, duplicated services.

### 3. Follow the main architecture

The application should feel like one coherent system, not stitched-together islands.

### 4. Favor end-to-end working flows

A feature is only complete if:

* schema/types are correct
* backend logic works
* frontend consumes it correctly
* the user can actually use it

### 5. Prefer working integration over theoretical perfection

If needed, choose the strongest practical architecture and implement it now.
